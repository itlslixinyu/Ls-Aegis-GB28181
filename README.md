## 安装运行

需要Node.js 24及以上。

```powershell
npm install
npm start
```

打开 [本地平台](http://localhost:3000/)。首次访问创建管理员，密码至少12位；没有预置账号密码。`npm start`先构建前端再启动后端。开发时另开终端运行`npm run dev`，5173端口代理API到3000。

```powershell
npm test
npm run typecheck
npm run build
```

## 使用流程

1. 在“国标设备”录入20位设备编号、设置独立接入密码；在设备端配置平台地址、国标域、编号和端口。档案创建不代表设备已注册。
2. 设备上线后同步目录；在“实时监控”选择1、4、9、16、25或36画面，先选窗口再选通道。通道列表每页32路，可跨页搜索；翻页保留正在播放的画面，单画面保留选中通道，缩小布局关闭多余预览。管理员可在左侧云台面板按住方向/变焦，松开停止；后端另有最长3秒停止保护。协议应答不等于物理动作确认。
3. 在“录像回放”选择在线通道及最多24小时范围，等待设备返回录像。选中结果发起独立回放，可暂停、恢复、倍速与跳转；设备不支持时显示失败原因。无时区设备时间按UTC+08解释，接口返回UTC时间，页面使用浏览器当地时间。
4. 在“国标级联”添加上级平台、接入密码和本平台对上级使用的编号；选择UDP或TCP信令，填写上级信令IPv4、端口及上级媒体接收IPv4。先保存草稿，选择共享通道并配置20位上级通道编号，再点击“注册”。仅共享的通道可被上级查询和点播。保存档案不会自动注册，已启用的平台在服务重启后会尝试恢复注册。
5. 在设备行“传输设置”选择UDP、TCP被动接收或TCP主动接收；信令方式由设备注册连接自动识别。SIP同时在同一端口监听UDP/TCP。修改媒体方式前需结束该设备点播和录像任务。
6. 从录像查询结果点击“导出录像”，在“录像任务”查看进度和下载MP4分段；支持1/2/4倍导出（设备能力决定）。导出使用独立源流、用户权限和幂等编号，收到结束通知并确认文件后才显示完成。
7. 管理员在“录像计划”选择设备分组，勾选组内通道，再设置星期、起止时间、分段长度和保留天数，保存并启用。按Asia/Shanghai时区执行，支持跨日；统一停用会结束组内当前任务，修改或删除须等待任务收尾。再次启用可接续当前时段，手动结束任务则不重启当前时段。
8. 管理员在“分组权限”创建分组、批量移动设备并给只读账号授权分组。新只读账号默认无设备权限；其设备、统计、录像、告警和地图均受分组限制。云台、告警处置、位置编辑及订阅维护可通过自定义角色授权；级联、计划、账号授权和平台配置仍仅限系统管理员。
9. 在“告警管理”按级别、分组和时间检索设备上报，依次确认和处置，保留操作人、说明及时间；重复上报合并计数。
10. 在“设备地图”查看授权点位和未处置告警；管理员可填写WGS84经纬度或地图取点。未配置底图时显示明确标识的坐标网格。配置步骤见[告警、地图与分组权限说明](docs/alarms-map-permissions.md)。

11. 在“订阅管理”配置设备级告警或移动位置订阅，设置有效期和位置间隔。请求受理、设备接受和通知到达分别显示；可自动续订、离线重试与停用。
12. 在“历史轨迹”选择设备/目标和时间，查询实际位置采样、地图连线、逐点播放及CSV导出；设备地图详情也提供轨迹入口。详见[订阅与历史轨迹说明](docs/subscriptions-and-trajectories.md)。

## 本地配置

复制`.env.example`为`.env`并修改，重启生效。默认仅本机HTTP，SIP关闭、媒体未配置。

| 参数 | 用途 |
| --- | --- |
| SIP_ENABLED / SIP_HOST / SIP_PORT | 启用UDP SIP及监听地址/端口 |
| SIP_ID / SIP_DOMAIN | 平台20位编号与国标域 |
| SIP_PUBLIC_IP | 设备及上级可到达的本平台信令地址 |
| MEDIA_URL / MEDIA_SECRET | ZLMediaKit管理地址及密钥 |
| MEDIA_RTP_HOST | 设备可到达的媒体RTP接收地址 |
| MEDIA_PLAY_URL | 后端访问HTTP-FLV的内部地址，默认MEDIA_URL |
| MEDIA_AAC_PREVIEW_DEVICES | 可选，逗号分隔的国标设备编号，用于强制启用转换。显式设置下列任一 FFmpeg 配置后，实时预览按通道自动识别 H.265 + G.711A/U 并在网页出口转 AAC |
| MEDIA_AAC_PREVIEW_CONTAINER | 可选，提供 FFmpeg 的现有 Docker 容器名。不设置时使用本机 FFmpeg |
| MEDIA_RTP_BIND_IP | 可选，媒体节点本地的 RTP 监听 IP。可让原生媒体节点将 HTTP 管理端口留在回环地址，同时把国标 RTP 绑定到局域网网卡。留空沿用媒体节点默认设置 |
| MEDIA_AAC_PREVIEW_EXECUTABLE | 可选，FFmpeg 可执行文件，默认 ffmpeg。H.265 需支持 Enhanced FLV 的版本 |
| MEDIA_HOOK_TOKEN | 媒体发布回调专用随机凭据，不向浏览器回显 |
| MEDIA_RECORD_PATH | MP4 HTTP路径模板，默认`/record/rtp/{stream}/{date}/{file}` |
| POSITION_RETENTION_DAYS | 历史位置保留1～365天，默认30天 |
| MAP_TILE_URL / MAP_ATTRIBUTION | 可选自建XYZ瓦片模板及署名；默认不请求外部地图 |

浏览器仅访问平台同源流代理，不获取SIP密码或媒体管理密钥。媒体HTTP管理/播放端口应限制为后端网络可达，直接公开媒体端口的播放鉴权尚未实现。

## 录像存储与回调

录像文件存放在ZLMediaKit的MP4存储目录，平台数据库只保存任务与文件索引；平台通过同源鉴权代理下载文件。需要ZLMediaKit启用MP4录制、RTP代理及HTTP文件服务，确保磁盘空间和访问权限。所有环境参数的设置步骤见[录像与TCP操作说明](docs/recording-and-tcp.md)。

录像任务会在计划录制期间定期登记已封口的 MP4 分段。展开文件列表即可回放或下载，网页回放使用浏览器支持的原文件编码。

设备录像导出要求配置`MEDIA_HOOK_TOKEN`，并在ZLMediaKit启用`on_publish`回调，指向本平台`/api/hooks/media/publish?token=同一凭据`。发布回调为对应导出流从开始就开启MP4录制；缺少回调不把导出报告为成功。计划录像可在流就绪后调用录制API，也建议配置该回调。

回调凭据与媒体管理密钥分别设置。媒体节点必须能访问回调地址；平台HTTP默认监听本机，跨机器部署应通过受控反向代理连接。检查媒体HTTP文件路径与`MEDIA_RECORD_PATH`一致，启用虚拟主机或自定义录像目录时按实际路径调整。不要直接公开媒体管理端口或绕过平台的文件权限。

## 会话、数据与升级

直播可共享源流，回放各用独立源流。观看租约45秒，前端每15秒续租；最后观看者退出/租约过期时回收。级联保留独立观看引用，停止上级转发不会结束其他本地观看。单账号64个观看者、实例64个未释放源流是开发保护阈值，不是容量承诺。浏览器使用同源WebSocket-FLV，保留HTTP-FLV接口；反向代理需支持WebSocket升级。

数据库为`data/platform.db`，启动自动执行幂等迁移。迁移11增加独立用户资料表，原账号、密码、角色及授权保留；历史时间仅从真实审计回填，无法追溯则留空。迁移10增加注册平台身份表：同一平台重启保留未过期UDP绑定；身份变更、过期绑定及旧TCP连接须重新注册，旧库首次升级也须重新注册一次。v0.7迁移9增加订阅配置与历史位置表；保留旧数据，不默认订阅、不从手工点位伪造轨迹。v0.6迁移8增加设备分组、账号授权、位置、告警与处置记录；已有设备归入默认分组、已有viewer保留该分组访问，新建viewer须显式授权。v0.5迁移6/7增加TCP传输字段、录像计划、下载/录制任务和文件索引；此前迁移包含PTZ命令、级联档案/共享/对话及回放字段，保留现有账号和设备。重启将中断的命令和查询标为失败，尝试回收残留媒体和级联资源。旧`data/devices.json`只在首次迁移导入，原文件保留，无效数据不静默丢弃。

停止服务后备份整个`data`目录；恢复时整体还原。设备和上级密码保存为与国标域绑定的Digest HA1，不可明文回读；修改域后须重设密码。HA1仍是敏感认证材料，需要限制数据库访问。

已验证上述一台海康IPC直播，尚未完成真实NVR、其他真机业务/上级平台验收、TLS/复杂NAT/目录订阅、生产数据库/集群和性能验收；具体范围见开发状态。其余测试使用本机协议模拟器和媒体替身，不能代替真实视频、物理云台动作和设备兼容性测试。
