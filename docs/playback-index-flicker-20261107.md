# 拖入海康录像反复闪动与时间倒跳

当前基准规则以[按窗口顺序选择回放基准](playback-window-reference-20261107.md)为准：初始优先第1格，无录像才向后回退，同一基准补索引不反复跳时间。

后续用户要求取消首次自动跳转。当前版本按[当前时段无录像](playback-current-gap-20261107.md)执行：拖入和播放保持当前位置，无录像直接显示提示。本文记录闪动根因与当时修复证据。

## 复现与原因

正式平台先拖入模拟摄像机013，暂停首帧定位22:07:59；随后拖入海康到第2格。旧版本在较早索引陆续返回时，将共享时钟反复改到更早时段，实测观察到14:57:07，模拟窗口因此丢失source，海康播放器反复定位/切段。定位来自前端自动选首帧逻辑，不能将该现象归因为摄像机网络或编码故障。

## 修复

- `PlaybackWall.vue`：首次选择可用位置后锁定自动初始定位；新增通道或补充更早范围不会覆盖共享时间。手动定位、播放、查询范围变更仍遵守原逻辑。
- `ArchiveDayPlayer.vue`：元数据并发获取、按探测优先顺序发布，避免后段先返回就抢占第一帧；同步恢复缓存时立即通知时间轴。
- 增量索引保留仍有效的已确认分段，不因为重建过程暂时只有部分分段而清空当前播放器；相同分段内容不重复发布。移除文件仍从候选范围剔除。

## 验证

- 93项实际组件回归通过，覆盖新增通道不倒跳、乱序元数据、缓存立即发布、增量新文件不重载原视频；类型检查和生产构建通过。
- 正式浏览器再次先拖模拟013，再拖海康：时间维持22:07:59，未反复回退下午；开始播放后时间自然推进至22:08:21，模拟640×360和海康1920×1080均readyState4且无媒体错误。
- 这是现有海康IPC的归档文件回放测试，本轮未读取型号与固件，不构成新增厂商协议兼容性结论。
- 仅更新前端，未重启后端，不改变录像计划或摄像机编码。
- 截图：`.tmp/playback-hik-no-rewind-20261107.png`。

先前首帧方案中“后补更早范围会校正初始时间”的行为已被此版本替代，避免持续闪动。
