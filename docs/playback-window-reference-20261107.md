# 按窗口顺序选择回放基准

本规则为用户最新要求，替代先前“完全不自动初始定位”的解释。

## 当前交互

- 按监看墙实际位置，从左上第1格开始，依次第2、3、4格；九画面同样依窗口顺序。空窗口跳过。
- 首个在查询起止范围内有已确认录像的窗口作为初始基准：当前时间在其录像范围内则保持，否则定位其首个有效录像时刻，显示该帧。
- 高优先窗口仍在索引且尚未找到有效录像时等待，不因为后排响应更快就提前选择。高优先窗口确认无有效录像后再回退后续窗口。
- 确定基准后所有窗口仍使用同一时钟；某一路在基准时刻没有录像，显示“当前时段无录像”，不各自跳时间。
- 同一基准继续补齐更早索引不会反复重定位。用户手动定位或已经开始播放后，不被后续索引/新增通道覆盖；查询日期或范围改变后重新选择基准。

## 修改及验证

- `PlaybackWall.vue` 增加按实际cells顺序的基准选择及交互锁定；平台播放器上报索引完成状态，`RecordingCenter.vue` 按窗口保存并传递，避免将未完成误判为没有录像。设备录像复用同一基准逻辑，范围来自已完成的设备查询。
- 类型检查和生产构建通过。回归包含窗口顺序与响应顺序不一致、第一格等待、第一至第四格逐级回退、手动定位保护、播放前索引未完成、缓存范围和增量索引。
- 正式浏览器：海康第1格先定位13:43:57并显示1920×1080首帧，模拟013放第2格时显示当前时段无录像，共享时间不改为模拟录像的22点。
- 正式浏览器：查询15:00—16:00，将模拟013/014/015分别放1/2/3格（范围内无录像）、海康放第4格，前三格均显示提示，第4格显示15:00对应画面，readyState4。第2、3格作为回退基准由自动测试覆盖。
