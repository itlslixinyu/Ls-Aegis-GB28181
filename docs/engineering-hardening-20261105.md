# 现有业务工程加固与验收（2026-11-05）

本轮范围为既有设备、预览、录像业务与工程基础，不新增业务模块，不替换框架，不改变摄像机编码。以下区分代码回归、隔离进程和真机证据，不据此宣称全部摄像机/录像机均兼容。

## 已完成的代码加固

- 将HTTP异常、JSON请求校验与成功响应提取到 `backend/lib/http.mjs`，保持 `{data,requestId}` / `{error,requestId}` 契约与204语义。启动与信号处理独立到 `backend/main.mjs`，原后端直接启动方式仍兼容。
- 写请求读取JSON后再次校验会话、CSRF、当前功能权限和URL中设备/通道范围，修复慢请求跨越撤权、移组或注销后仍可能执行的问题。请求体仍限制16KiB；增加请求体30秒与请求头10秒的接收期限。已受理的协议异步任务仍遵循原有生命周期，不能把已受理等同业务完成。
- 密码哈希缺失、损坏或长度不合法时安全拒绝，不因 `timingSafeEqual` 长度异常产生500；不重写任何现有密码。
- SQLite连接配置5秒忙等待；沿用同步、参数化SQL与既有事务边界。此项不代表支持多实例共享同一库。
- 录像导出幂等键限定1～100位ASCII字母、数字及 `_.:-`；同一账号相同键和参数复用原任务，参数变化拒绝。16次重复调用验证只有一个任务。继续使用数据库唯一约束防重复调度，未改变任务归属。
- 增加分环境启动、只读健康检查与数据库运维脚本；忽略环境秘密文件及 `.tmp/`。媒体原生运行文件当前位于 `.tmp/`，没有作为“调试文件”删除，以免中断实际服务。

## 环境与启动

默认 `npm start` 保留本地 `.env` 的行为。已部署环境也可继续 `node --env-file-if-exists=.env backend/server.mjs`。

```powershell
Copy-Item .env.development.example .env.development
npm run build
npm run start:development
```

测试与部署分别复制 `.env.test.example` / `.env.production.example`，使用 `npm run start:test` / `npm run start:production`。显式环境文件不存在会拒绝启动，绝不回退本机真实设备的 `.env`；已注入的操作系统变量优先。示例默认禁用SIP，数据库分别放在 `data/development`、`data/test`、`data/production`。生产示例启用Secure Cookie，须先配置HTTPS反向代理。首次选新数据库会进入平台初始化，不能误认为原账号丢失。

`HTTP_HOST` 控制HTTP监听地址，默认回环；`PLATFORM_DATABASE` 可指定持久库路径。不得让多个服务实例同时调度同一个数据库中的录像计划。接入配置页面已保存的配置文件仍按原有规则生效。

## 数据库和部署巡检

```powershell
npm run db:check -- data/platform.db
npm run db:backup -- data/platform.db
npm run db:migrate -- <目标数据库路径>
npm run healthcheck
```

check只读，不创建缺失库；backup使用SQLite在线一致性备份；migrate对现有库先备份再运行已登记的幂等迁移，检查完整性和外键。本轮没有新增库表变更，当前仍为迁移12。隔离库初始化及重复迁移已验证，未拿正式库执行迁移实验。既有迁移定义仍在store内，后续新增结构须带编号和迁移验证，不允许直接手工改正式表。

健康检查可用 `PLATFORM_URL` 指定站点，5秒超时，失败/降级以非零退出码返回，不输出凭据。JSON启动日志与requestId支持进程监控和问题追踪。健康ok只代表平台可用，媒体unchecked并不等于视频已就绪；仍需业务验收。
