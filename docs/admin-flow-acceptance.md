## 菜单及账号

菜单已按接入准备、日常监控、录像、事件位置、集成及审计排序：接入配置→用户管理→分组授权→国标设备→实时监控→录像计划→录像回放→录像任务→订阅管理→告警管理→设备地图→历史轨迹→国标级联→操作审计。打开后仍默认设备页，便于日常使用；只读角色继续隐藏管理员功能。

用户最初提供的凭据实际登录失败。收到用户明确重置授权后，先停止经进程命令行确认的本项目服务、备份整个data，再重置admin散列并撤销其旧登录，隐藏重启同一应用。备份：`backups/pre-admin-reset-1793508215000/data`。没有在报告、脚本或日志中保存明文密码。重置后浏览器和独立API登录均成功，角色为admin。

另发现：原设备“123”的编号与当前平台编号相同，均为`41010500002000000001`。真实接入前需核对实际设备的独立国标编号；本轮保留原档案，没有自动改写。WVP示例的平台编号不应直接当作摄像机编号。

## 已执行的业务流程

[可重复验收脚本](../scripts/admin-acceptance.mjs)通过环境变量 `ACCEPTANCE_PASSWORD`读取密码，只允许本机目标；Cookie和CSRF仅在内存使用。使用真实admin创建带时间戳的临时分组、设备及viewer，结束时清理本次创建的资源，保留操作审计。

实际32项检查通过，逐项结果及时间见[JSON原始结果](admin-flow-results.json)：

- 新建分组、添加/修改设备、重复编号拒绝、设备接入密码配置、UDP/TCP主动/TCP被动参数保存与回读、批量入组、搜索分页。
- 手工WGS84点位保存及地图读取；手工点位没有伪造成历史轨迹。
- 新viewer默认无设备；授权后仅见测试设备；禁止其新增设备；撤权后列表、地图及详情即时失权。
- 两类订阅受理后保持waiting，不声称已被设备接受；启用订阅时阻止删除设备；停用后收敛至disabled。
- 配置、媒体节点、计划、任务、告警、地图配置、级联及审计入口读取。
- 未注册设备同步目录明确拒绝；通道保持为空；历史轨迹为空。

API测试前后均为1个账号、1台原有设备和1个默认分组，临时资源全部清理。没有更改原设备档案。审计记录因真实操作而增加。

浏览器还实际执行admin登录→设备页→新增“验收界面临时设备”→列表回显待注册→通道空提示→实时监控无通道、云台不可操作；随后通过API清理该确切编号和名称的临时设备。截图为操作时证据，不表示已有真实摄像机在线。

## 没有完成的现场流程

| 步骤 | 本次结论 | 所缺条件 |

| 注册、心跳、目录和通道 | 未验收；档案添加不等于接入 | 启用SIP、实际IPC/NVR及其接入参数 |
| 预览、真实解码、物理云台 | 未验收 | 在线通道、可达RTP及真实ZLMediaKit |
| 录像检索、回放、下载、计划文件 | 未验收 | 设备录像、MP4录制/回调/磁盘；实际文件验证 |
| 告警/位置通知、历史轨迹 | 未验收 | 设备真实事件和GPS采样；当前只验证等待与停用 |
| 级联互通和转发 | 未验收 | 实际上级平台、共享通道及双向媒体网络 |
