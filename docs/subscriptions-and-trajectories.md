# 告警订阅、移动位置订阅与历史轨迹

v0.7.0，2026-11-01。前后端与本机模拟验证已完成，尚未连接真实IPC/NVR。支持情况需按现场固件与国标版本验收。

## 配置订阅

管理员进入“订阅管理”→“配置订阅”，选择已建档设备及告警/移动位置类型。每台设备每类一个配置，重复保存更新原配置。默认有效期3600秒、位置上报间隔5秒；允许有效期30～86400秒、间隔1～3600秒且不超过有效期。勾选启用后保存，HTTP返回202表示受理。

设备离线或SIP关闭时显示“等待接入”和原因；上线后自动尝试。默认正式配置不创建或启用订阅。实例最多10000条订阅配置、同时8个请求；这些是开发保护上限，不是设备容量承诺。

状态含义：

| 状态 | 实际含义 |
| --- | --- |
| 等待接入 | SIP未启用或设备离线，保留配置意图 |
| 请求中 | SUBSCRIBE事务尚未结束 |
| 设备已接受·待通知 | 收到成功响应，尚未收到对应NOTIFY |
| 通知正常 / 设备待授权 | 收到active或pending订阅通知；不表示一定有告警或GPS数据 |
| 订阅异常 | 对端拒绝、响应无效或32秒通知期限届满；错误可查看 |
| 取消中 / 已停用 | 停止续订并尝试Expires:0取消；已知对话可等待最终空终止通知 |

成功响应须有To标签及合法Expires，接受时间、到期和通知时间分别显示。按协商期限约80%续订，沿用Call-ID、双方标签和递增CSeq；短期限会相应缩短续订时间。失败5秒起指数退避，最长5分钟，启用期间继续重试。设备423要求更长有效期时，管理员修改配置重试；尚不自动调整设备要求的Min-Expires。

停用会中止本地未结束请求，不处理该订阅迟到的业务内容，已知对话发Expires:0。未确认标签的请求等待通知确认或有效期截止；重启后无法恢复的旧对端对话也可能持续到原期限届满。已停用说明本地已停止续订，不能据此声称现场设备已经关闭全部主动上报。设备不依赖订阅而发送的MESSAGE主动通知仍按原规则接收。

配置与启停进入操作审计；viewer仅能查看当前获授权设备的订阅，没有设置/停用权限。删除设备前须停止其订阅并等取消流程完成。

## 通知与协议边界

两类订阅分别建对话，均使用presence事件，XML Query的CmdType区分Alarm/MobilePosition，位置带Interval。通知须来自当前注册端点，匹配Call-ID、双方标签、Event、CSeq及对应XML类型；业务目标只能是本设备或自身目录通道。重复CSeq不重复入库，倒退序号拒绝；初始NOTIFY早于200也可关联，最终terminated空通知可正确应答。

SUBSCRIBE的Contact明确标注UDP/TCP传输；响应及NOTIFY的Contact只允许已注册直连端点及一致的传输，不跟随任意目标；带Record-Route返回可见错误。NOTIFY使用SIP响应；原MESSAGE告警仍保留XML业务应答。

服务重启保留启用意图，丢弃旧内存对话；设备重新注册后建立新对话。正常关闭中止待办，对最多256个已知对话尝试有界取消，未确认/超出数量/异常退出的对端会话自然到期。没有实现TLS、代理路由、分叉、presence以外事件包、订阅401/407 Digest挑战或跨实例对话恢复。不要把本机通过当作所有设备兼容。

行为参考：[WVP订阅实现](https://github.com/648540858/wvp-GB28181-pro/blob/master/src/main/java/com/genersoft/iot/vmp/gb28181/transmit/cmd/impl/SIPCommander.java)；对话与通知生命周期参照[RFC 6665](https://www.rfc-editor.org/rfc/rfc6665.html)。代码独立实现。

## 历史轨迹

只有通过校验的设备MobilePosition上报生成历史点，既支持主动MESSAGE，也支持对应订阅NOTIFY。经纬度使用WGS84；时间、坐标、目标归属校验后落库。没有时区的时间按UTC+08解释，超过当前时间5分钟的未来时间拒绝。

历史与当前展示位置独立：手工定位仍优先，晚到但在保留期内的设备位置可进入历史而不覆盖新位置。按设备、目标、事件时间及坐标去重，按事件时间与ID排序。不同通道单独检索，不混连；目录已经移除的历史目标仍可查询。每设备每分钟最多600条新位置，超限返回486。

进入“历史轨迹”选设备和目标，设置起止时间后查询；或从“设备地图”详情点击“历史轨迹”。最多查询7天，默认按1000点加载，点击“加载后续采样点”继续。接口单页1～2000点，游标冻结本次采样集合；页面最多加载10000点，超过请缩小范围。新到/补报点需重新查询。

地图绘制实际采样点连线，间隔超过5分钟或跨180°经线断开。起终点与当前播放点分别标记。连线不代表道路，没有对缺失位置补点或插值。底图沿用MAP_TILE_URL/MAP_ATTRIBUTION；未配置时显示明确标注的经纬度网格。

逐点播放每0.5秒前进一个已加载点，可暂停、拖进度及查看表格点位；这不是按实际时长播放。表格每页50点，仅格式化显示到6位小数，CSV保留原数值。“导出已加载点”仅导出已加载数据，含目标编号、UTC时间、WGS84经纬度，不冒充完整查询结果。

轨迹及目标列表均按当前设备分组授权；移组或撤权后接口立即拒绝历史读取，页面每15秒复核设备访问并在失败时清空已加载视图。已下载的文件无法追溯撤回。

## 保存与升级

在`.env`设置`POSITION_RETENTION_DAYS=30`，允许1～365天，重启生效。查询立即过滤超期事件；每分钟分批删除最多10000条过期采样。缩短期限会清理超期历史，旧备份按部署方策略保管。

迁移9新增device_subscriptions和position_history及索引，保留已有账号、设备、告警与手工位置。不会从当前点位补造历史，也不会默认启用订阅。升级前备份完整data目录。

62项完整测试通过，新增9项含本机真实UDP/TCP连接、模拟告警/位置通知、取消/续订、异常、权限与历史分页。浏览器检查订阅参数回读/停用、轨迹检索/播放/CSV导出和桌面/窄屏、只读范围。18个界面测试采样及所有截图都来自隔离数据库；CSV核验18行与UTC/WGS84列。真实设备/固件、真实地图服务与现场GPS精度尚未验收。
