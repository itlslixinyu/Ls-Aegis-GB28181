# 按线索检索历史录像

日期：2026-11-08。用户将持续自动分析纠正为“根据提供的信息去录像里面查找”。本轮采用按需查询，不启用持续全量索引或逐帧上传。

## 使用方式

AI → 智能检索，选择“按线索检索历史录像”，输入文字线索或选择参考图，指定通道及开始、结束时间，提交后异步处理。未指定通道时仅查询当前有权访问的通道。也可切回“仅查已有分析画面”复用先前索引。

后台先按文件、通道和录像时间选择范围，再读取实际时长并定位取帧，合并成带角标的拼图交给DeepSeek查找候选；候选附近再取少量画面细查。匹配画面保留录像时间、原文件、文件内偏移，详情提供“定位原录像”。新增或刷新页面不会自动发起查找；刷新可恢复上次任务结果、文字和起止时间。没有命中只说明本次抽样没有找到，不代表整段录像不存在目标。

## 控制成本与资源

- 单次最多24小时、64个通道；最多抽查12个文件、32张采样、4次批量模型调用。文件超限会分布抽取并明确提示未完全覆盖，建议缩小范围。每个文件首先采集所选范围起点及中间点，候选再取前后10秒附近；不是逐帧扫描，不保证短暂出现的目标被命中。
- 全部账号共用一个历史检索执行任务；每账号最多1个待处理任务、每小时6次，队列共3个；全平台每天最多120次历史检索模型调用。调用计数是保护上限，不是费用承诺，失败请求也可能被服务商计费。
- 单线程、低进程优先级、30秒单次媒体读取超时、2MB取帧输出上限、20分钟任务截止时间。预览观看者达到9个、在录/收尾任务达到4个，或手动画面分析繁忙时后台等待让行。并发阈值是保守保护，不代表所有硬件都已完成性能基准。
- 仅HTTP读取既有MP4文件，利用文件偏移取帧；不新增SIP点播、不修改设备编码、不启停录像计划。不会下载或扫描设备内尚未归档到平台的录像；读取失败会标注部分覆盖或失败。
- 相同账号、线索/参考图、范围、文件集合与模型的进行中/已完成查询复用；重启中断的查询明确标记，不自动重放付费任务。源文件或当前权限失效时不可再读关联结果。

## 权限及数据

POST /api/v1/ai/history-searches要求ai.analyze与recording.view、设备分组范围及CSRF；GET /:id和POST /:id/cancel限任务本人。设备导出文件还需满足原任务归属约束。查询条件和任务记录在ai_history_searches；关联候选在ai_history_matches；ai_jobs新增recordingFileId、frameOffset，源文件删除时关联候选级联清理。录像实际播放继续使用原有授权文件接口，管理密钥不进入浏览器。没有修改正式账号授权。

迁移015只新增AI表及关联列，不改录像计划、任务或文件内容。数据库更新前备份至backups/database-1794075443823-d55f7120/platform.db，旧前端副本位于.tmp/ai-before-history-dist。

## 运行依赖

本机为只绑定回环地址的原生媒体节点，原有Docker FFmpeg不能直接访问该回环MP4地址。为历史检索单独安装Windows FFmpeg/ffprobe，不改变原有实时音频转码配置：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-ai-media.ps1
```

脚本只下载Gyan官方发布镜像的9.0.2 essentials，校验GitHub发布资产SHA256，再解压至data/ai-tools；保留包内许可证。输出AI_ARCHIVE_FFMPEG_EXECUTABLE环境配置行，本机已写入.env并随本次重启生效。该变量只作用于历史检索。Linux或已具备工具的部署可设为自身FFmpeg路径，ffprobe需同目录。若沿用Docker工具读取本机媒体，可通过AI_ARCHIVE_MEDIA_HOST指定容器可达的媒体主机，不开放防火墙也不修改媒体监听地址。
