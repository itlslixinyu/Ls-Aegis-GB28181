# Agent 与 Skill 设计

本方案服务于 docs/workflows.md 中的独立开发路线。角色是分工模板，Skill 是可复用任务步骤；文档不会自动启动 Agent 或安装全局 Skill。

## 角色

| Agent角色 | 输入与职责 | 输出 | 文件范围 |
| --- | --- | --- | --- |
| 主Agent / 架构协调 | 用户目标、当前实现；拆分功能、确定依赖、统一契约、集成验收 | 任务边界、设计决策、集成结果 | AGENTS.md、docs、共享配置 |
| 前端Agent | 页面流程、API契约；列表/表单、分屏、播放器、事件订阅 | 页面与交互、加载/空/失败状态、验证结果 | frontend |
| 业务后端Agent | API契约、权限和数据模型；设备、任务、观看者、审计 | 服务接口、迁移、关键接口测试 | backend业务模块、未来数据库目录 |
| SIP协议Agent | 目标版本、设备配置、原始抓包；注册、目录、事务和点播 | 协议适配、事务测试、设备联调记录 | 未来SIP模块、协议测试 |
| 媒体Agent | 媒体节点能力、播放参数；分配、回调、授权、回收 | 媒体适配、会话状态机、补偿测试 | 未来媒体模块、会话测试 |
| 验证Agent | 实际变更、验收条件、环境 | 可复现问题、测试证据、未验证项 | 测试及验收记录；实现修复交回所属角色 |

不为尚不存在的模块创建空代码目录。角色开始任务前确认实际代码路径。小任务合并角色，协议与媒体改动按接口依赖顺序推进。

## 协作交接格式

每项任务提供：目标、允许修改的文件、依赖契约、输入样例、验收条件、不可执行的外部动作。结果返回：修改文件、行为变化、验证命令与结果、风险/未验证项、需要主Agent整合的事项。

共享字段或状态机有争议时先在 docs/workflows.md 记录决定，再实施；不要让前后端分别猜测。依赖未完成时可使用明确标注的开发模拟适配器，不能据此报告真实设备验收通过。

## 项目Skill目录

| Skill | 触发场景 | 主要产出 |
| --- | --- | --- |
| gb-feature-contract | 开始一个跨前后端业务功能或改变接口 | 流程、接口、数据与验收约定 |
| gb-frontend-flow | 实现设备管理、监控和录像等前端交互 | 页面、状态反馈、API接入 |
| gb-backend-service | 实现设备、任务、权限等业务API | 后端实现与关键行为测试 |
| gb-sip-integration | 实现或排查SIP注册、目录、点播信令 | 协议适配和联调证据 |
| gb-media-session | 实现媒体节点、播放会话及回收 | 媒体适配和会话生命周期 |
| gb-acceptance | 验收闭环或排查本地访问/设备联调故障 | 验证报告与可复现问题 |

Skill位于项目 skills/，通过读取对应 SKILL.md 使用；尚未注册到全局技能目录。示例：请按 skills/gb-feature-contract/SKILL.md 设计设备目录同步功能，再按后端和前端 Skill 实施。

## 推荐推进方式

M1：主Agent确定契约，业务后端建立基础服务，前端接入，验证角色验收。M2：先用SIP Skill建立协议事务测试，再在授权设备上联调。M3：媒体和SIP角色先约定会话及回调，再完成观看者租约和资源补偿，最后验证真实播放与断线回收。

Agent数量由任务决定，不固定运行六个；外部设备控制和部署仍遵守当次授权。
