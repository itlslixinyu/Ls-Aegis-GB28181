## 通过项

1. 使用用户提供的设备登录凭据读取型号、固件与现有配置。
2. 原国标平台1未启用。备份后启用并指向本机，设置独立随机SIP接入凭据；未改动摄像机管理账号密码。平台只存SIP HA1摘要，浏览器不获取接入密码或媒体管理密钥。
3. 实际注册成功，平台显示设备在线；目录同步任务 succeeded，返回1路在线 Camera 01。
4. 实际INVITE/ACK点播成功，媒体节点收到来自摄像机的TCP RTP，识别到H.265 1920×1080视频。
5. 平台会话 ready；浏览器实际解码视频，videoWidth=1920、videoHeight=1080、readyState=4、paused=false，截图可见摄像机实时画面。
6. 原有平台浏览器页已切为实时监控单画面并保留，用户可直接查看。

本轮仅修改本机接入配置、添加设备档案及部署媒体容器，未修改业务源码，也未把此前93项回归描述为本轮重新运行。录像查询/回放/下载、计划录像、云台、告警、订阅及级联等功能仍需分别实机验收；当前单型号直播结果不代表完整标准兼容认证。

## 调试与运行记录

- 初始媒体端口池40000～40020小于当前ZLMediaKit所需最小范围，调整为40000～40099后可正常分配RTP接收器。
- UDP媒体未收流；尝试增加仅限该摄像机来源的Windows防火墙规则时被操作系统拒绝，未新增规则。现用TCP-ACTIVE实测成功，未关闭防火墙。
- 平台服务重启后进程47276；保存配置位于私有数据目录 data/access-config.json，媒体配置及持久化录像目录位于 data/media/。
- 媒体容器设置 restart unless-stopped；Docker引擎启动后可用 `docker start ls-aegis-media` 启动已有容器。平台仍按 `npm start` 运行，未设置Windows开机自启。
- 数据库、原平台脱敏配置及原摄像机SIP配置备份位于 backups/hikvision-20261103/。实际画面凭证位于被Git忽略的 data/evidence/hikvision-live-20261103.jpg，不加入公开截图目录。
