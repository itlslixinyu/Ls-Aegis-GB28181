# 实时监控超过32路通道审计

## 本轮修复

- 从 36 格缩到较小布局时，如果当前选中通道在被移除的后排，移到第一格保留，并正确更新选中位置。
- 关闭处于放大状态的窗口，或刷新后该放大通道已离线，自动恢复完整分屏，避免其他窗口继续隐藏。
- 手动选通道、关闭单格、切换分屏及刷新列表时清理过期批量提示，避免仍显示旧的已安排路数。
- 全部关闭后将入口自动点播标记为已处理，迟到的初始通道请求不再把画面重新打开。
- 放大/还原会取消尚未完成的批量打开，避免迟到结果覆盖用户当前操作；非法窗口序号不参与放大。

本轮产品变更仅在 `frontend/src/components/Monitoring.vue`，未修改正式后端、接口、数据库或录像调度逻辑，无需重启平台或媒体节点。

## 隔离场景与边界

使用 `backend/test-support/monitoring-fixture.mjs` 创建独立临时数据库、仅监听回环地址的测试 HTTP 服务和 SIP/媒体替身：模拟一台 128 路 NVR，前 64 路离线、后 64 路在线；测试只读账号只获该 NVR 分组权限，另有无权设备与后台录像保护通道。媒体只发送 FLV 文件头，不生成真实视频画面，因此本轮是分页、交互、会话和资源回收测试，**不是 36 路真实解码性能或 NVR 国标兼容性验收**。

`scripts/monitoring-browser-fixture.mjs` 启动浏览器验证环境、记录观测结果及延迟请求控制；浏览器实际操作使用 CUA。测试期间正式平台持续运行，仅以只读方式计算正式录像计划快照；未连接或控制真实设备。
