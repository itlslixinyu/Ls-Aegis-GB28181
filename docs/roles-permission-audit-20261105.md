# 角色与设备范围复验（2026-11-05）

本轮使用真实浏览器页面、临时内存数据库和隔离测试账号，不变更正式账号授权。设备档案与告警是明确的模拟数据，SIP适配器禁用网络；本轮不作为摄像机物理动作或协议兼容性验收。

## 发现与修复

1. 服务端原本即时校验，但菜单依赖15秒轮询。新增同源、Cookie会话绑定的 `GET /api/v1/me/authorization-events` 通知连接；角色、账号范围和设备移组提交后通知浏览器重新获取 `/me`，更新菜单、按钮及业务数据。事件不携带密码、密钥或授权明细。断线自动重连并获取快照，原15秒轮询及403刷新保留为降级路径。
2. 仅移动设备所属分组不会改变账号授权版本，页面可能仍显示旧设备。通知增加前端刷新代次，重新加载业务数据；用户管理、配置等页面不因无关设备移动而丢失编辑。
3. 收回已选分组后，设备、告警、地图与订阅的已保存分组筛选可能失效。加载最新授权分组后清除失效项；有效筛选继续保留。
4. 地图详情向缺少权限的角色显示预览及历史轨迹入口，现按权限显示。告警行“查看 / 处理”改为按告警处置权限判断。
5. 移组会回收失权观看和下载，但已开始的云台动作仍可能等待自动停止期限。现在移组/分组授权变化立即停止失权动作，不停止其他账号仍有权操作的通道。

通知连接上限：每会话8条、每实例256条；断开、退出、会话失效及平台关闭均清理连接。会话每秒复核，通知背压时关闭连接并重连。通知在请求进行中到达时再取快照，防止迟到响应覆盖新权限；旧账号迟到事件不影响新登录账号。

全量157项隔离回归通过；最终通知时序与旧账号事件保护调整后，相关10项回归再次通过。类型检查、构建通过。构建仍提示入口包超过500kB，是体积建议。
