# YOLO 本地目标检测与图片标注

2026-11-08 实施，复用现有 AI 页面，不新增业务模块。使用项目 gb-backend-service、gb-frontend-flow、gb-acceptance 工作约定。

## 实际行为

- 画面分析 → 上传图片：默认勾选“使用本地 YOLO 检测并标注”，点击开始分析后保存图片并按需检测，不要求 DeepSeek 开关或密钥。通道抓拍的文字描述仍走已有 DeepSeek；录像本地分析继续使用原有检索入口。
- 在分析记录、录像分析画面或匹配结果中打开详情，点击“本地目标标注”。再次打开只读缓存，不自动启动模型；重复请求复用缓存。展示目标框、中文类别、置信度及文字结果列表；相邻文字采用避让布局，目标框位置不变。
- 来源于录像的结果保留“定位原录像”，沿用受权限保护的文件地址和文件内时间偏移；上传图片没有录像来源，不伪造回放入口。
- YOLO 为80类常见目标检测，不能描述任意动作、推断身份或可靠判断颜色。夜间、遮挡和小目标会漏检；Chinese-CLIP 继续承担自由描述与图像相似检索，二者职责不同。检测框没有用于改变录像计划或触发新告警。

## 后端与数据

新增 backend/ai/yolo.mjs、yolo-worker.mjs，扩展 ai/routes.mjs、service.mjs、history-search.mjs。本地固定模型 SHA256 为 634279b40c07c6391472c51ad45b81ebc48706a9a1fe72dd3396322acd0c053b；每个检测进程校验后才加载。CPU 单线程、低于正常优先级，单实例最多一个检测进程，30秒超时，退出、断连及撤权具有取消路径。不联网下载模型、不发送图片至外部服务。

缓存键为实际 JPEG SHA256 + 模型/阈值/预处理版本，迁移19新增 ai_detection_cache，只存目标框和元数据，不重复存图片；最多1000项，使用既有保留天数。当前用户、原图存在性、录像和分组权限在读取缓存前、检测中及发布前复核，不能凭缓存绕过授权。源图删除后不可通过检测接口取回缓存结果。文件缓存可跨窗口及服务重启复用。

资源保护：历史检索或其他分析正在运行、在录/收尾任务达到4个、观看租约达到9个、可用内存不足768MiB时，新检测返回明确的繁忙提示；运行中负载或权限变化会取消检测。历史检索也避让在途 YOLO。以上是本机原型保护阈值，不是多路性能承诺。

接口沿用登录、CSRF 和服务端权限：

- GET/POST /api/v1/ai/analyses/{id}/detections
- GET/POST /api/v1/ai/history-searches/{searchId}/samples/{sampleId}/detections

GET 返回已有结果或 status=not_analyzed，不加载模型。POST 需 ai.analyze，命中缓存直接返回；成功结果包含 status、model、width、height、checkedAt、cached、boxes。boxes 含 classId、label、confidence 和归一化 x/y/width/height，最多100个；无目标和未分析分开表示。不是长期视频任务，无无限后台队列。
