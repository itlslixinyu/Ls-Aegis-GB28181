# TCP、录像下载与录像计划操作说明

版本v0.7.0，2026-11-01。以下为本地开发功能的配置方式，尚未经过真实摄像机、固件或上级平台验收。

## TCP接入

设置`.env`的`SIP_ENABLED=1`，并将`SIP_HOST`、`SIP_PUBLIC_IP`、`MEDIA_RTP_HOST`设为实际可达的IPv4地址，重启平台。SIP在同一个`SIP_PORT`同时监听UDP和TCP；设备选择TCP后通过同一连接完成注册、心跳和控制。信令方式由认证注册记录，无需在设备档案中重复设置。

在设备列表点击“传输设置”：

| 方式 | 本平台/媒体节点 | 设备 |
| --- | --- | --- |
| UDP | 接收UDP RTP | 向媒体节点发送UDP |
| TCP被动接收 | 媒体节点监听TCP，SDP setup:passive | 主动连接媒体节点 |
| TCP主动接收 | 媒体节点连接设备，SDP setup:active | 监听TCP并在应答中返回地址/端口 |

当前TCP主动接收限定连接设备注册IPv4及应答端口，不支持通过任意SDP地址转向第三方主机。修改传输方式前应结束该设备的直播、回放和录像任务。级联平台的“信令传输”可独立选择UDP/TCP；上级媒体SDP支持TCP主/被动转发。TCP被动转发监听端口需要网络访问控制，只允许预期上级接入。

TCP实现分片/粘包、Content-Length分帧、CRLF保活、连接复用和断线处理；不是TLS或完整复杂SIP路由/NAT实现。设备断线后需重新注册。

## 媒体节点与录像文件

ZLMediaKit需编译启用MP4与RTP代理，管理接口可用，MP4目录可写且磁盘空间充足。平台调用`openRtpServer`、`startRecord`、`stopRecord`、`getMP4RecordFile`、`deleteRecordDirectory`及TCP/RTP转发相关API。

文件保存在媒体节点，平台只索引文件。下载由后端访问媒体HTTP文件服务，再按当前用户权限代理到浏览器。默认路径模板：

```dotenv
MEDIA_RECORD_PATH=/record/rtp/{stream}/{date}/{file}
```

如ZLMediaKit启用虚拟主机或使用其他HTTP录像目录，修改模板与媒体端实际路径一致，例如在`/record/`后插入固定的`__defaultVhost__/`。`MEDIA_PLAY_URL`填写后端可访问的媒体HTTP根地址。文件名与日期来自媒体API并经过过滤，不接受浏览器指定媒体路径。

## 发布回调与完整导出

设备录像导出需要在第一批媒体数据进入时开启MP4，避免等到流就绪后才开始录制造成缺失开头。

1. 在平台`.env`设置独立、足够长的随机`MEDIA_HOOK_TOKEN`，与`MEDIA_SECRET`分开；重启生效。
2. 在ZLMediaKit已有配置中设置下面两项，不覆盖其他服务所需配置：

```ini
[hook]
enable=1
on_publish=http://平台可达地址:3000/api/hooks/media/publish?token=与MEDIA_HOOK_TOKEN相同的值
```

3. 媒体节点必须能访问该地址。平台HTTP默认只监听127.0.0.1；同机部署可用本机地址，跨机器部署需通过受控反向代理访问平台。正式部署配置HTTPS及访问控制，避免凭据出现在公开日志。
4. 回调只对平台管理的录像流启用MP4并返回对应分段长度。缺少发布回调或凭据错误时，设备导出不报告完整成功。某些媒体配置会跳过本机/管理身份发布的认证回调，需要实际验证回调到达。
5. 管理接口在线不等于回调、磁盘、文件HTTP路径或视频可用，需分别检查。后台不自动改写媒体节点全局配置。

## 设备录像下载

在“录像回放”查询设备历史录像，选择1/2/4倍导出速度，点击“导出录像”。单次范围最多24小时，且不能超过已查询条目。速度由设备支持决定；设备不支持或结束通知超时会显示失败。

在“录像任务”查看：准备中→录制中→生成文件→已完成。平台使用独立Download源流和历史SSRC，不与实时预览或其他回放复用。结束通知必须匹配原Call-ID，随后等待30秒收集已完成MP4分段；无文件不显示成功。

展开文件列表逐个下载。支持单段HTTP Range，不通过前端把大文件整体读入内存；每次文件传输最长1小时或到登录到期，可用范围请求接续。管理员可查看全部任务，只读用户仅可查看和下载自己的任务。取消/故障/中断时保留已生成的部分文件，页面明确标识。

## 周期录像计划

管理员在“录像计划”创建名称、通道、执行星期、起止时间、分段长度和保留天数。默认草稿停用，勾选启用后按Asia/Shanghai（北京时间）执行。结束时间不晚于开始时间表示录制至次日，相同起止时间表示24小时。跨日计划归属于开始日期的星期。

同一通道的启用计划不能重叠。计划采用独立实时源流，文件按1～60分钟分段（UI提供1/5/15/60分钟）；保留1～365天。计划不写入摄像机/NVR的本地录像日程。

- 停用计划会结束当前任务；等待文件生成后可编辑/删除，重新启用可接续当前窗口。
- 手动“结束任务”只结束该次窗口，不在该窗口自动重开；下一次计划正常执行。
- 服务中断将旧任务标记中断并保留文件；重启回收旧源流后，只在仍有效的窗口内重开任务，停机期间不会补录。
- 设备离线等故障按60秒退避，同一时段最多3次尝试。实例最多8个录像任务，单账号最多4个；超过容量等待后续调度。这是开发保护阈值，不是生产容量承诺。
- 保留策略在任务创建时快照保存；到期后每分钟最多处理20个自有文件，媒体删除成功才删除索引，失败重试。积压和离线会延迟实际删除；不删除整个共享目录。

删除用户前须先处理其录像计划和活动任务；历史任务移交执行删除的管理员，保留既有文件清理策略。
